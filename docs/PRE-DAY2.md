# المهمة التحضيرية للجلسة القادمة

في الجلسة القادمة، سنتحقق من استجابة صفحة ويب ونلخص النتيجة وتاريخ التحقق ووقته في تقرير. ستشغّل هذه العملية في مستودعك. جهّز في بيئة Codespace الخاصة بك الملفين اللذين ستحتاج إليهما لذلك. يستغرق الإعداد نحو 10 دقائق. لا يلزم تسليم أي شيء.

## ما يجب تجهيزه

أنشئ الملفين التاليين داخل مجلد اسمه `pre_day2`.

- `pre_day2/template.md` — القالب الأصلي لنص التقرير
- `pre_day2/generate.sh` — البرنامج الذي ينشئ التقرير من القالب

تجد المحتوى في أسفل هذه الصفحة. سنقرأه ونشغّله في الجلسة القادمة. يكفي تجهيزه الآن.

## الخطوات

1. افتح بيئة Codespace التي استخدمتها اليوم. إذا كانت علامة التبويب الخاصة بها لا تزال مفتوحة، فارجع إليها. إذا أغلقتها، فافتح صفحة مستودعك على GitHub، واختر `Codespaces` من `Code` كما فعلت اليوم. ستظهر بيئة Codespace التي أنشأتها اليوم في القائمة، فانقر عليها. لا تنشئ بيئة جديدة.
2. أنشئ الملف الجديد `pre_day2/template.md` في قائمة الملفات. يوضح القسم التالي كيفية إنشائه.
3. انسخ محتوى المربع المعنون «template.md» أدناه والصقه، ثم احفظه كما فعلت اليوم.
4. أنشئ `pre_day2/generate.sh` بالطريقة نفسها واحفظه.
5. افتح الملفين وقارن محتواهما بمحتوى المربعين في هذه الصفحة للتأكد من تطابقهما.

يمكنك هذه المرة متابعة العمل على master دون إنشاء فرع. سنسجل التغييرات في الجلسة القادمة.

## كيفية إنشاء ملف جديد (عملية لم نتناولها في تدريب اليوم)

1. انقر بزر الفأرة الأيمن على سطر اسم مستودعك في أعلى قائمة الملفات (يُعرض بأحرف كبيرة).
2. اختر `New File...` (ملف جديد) من القائمة التي تظهر. سيظهر حقل لإدخال الاسم.
3. اكتب `pre_day2/template.md` واضغط على مفتاح Enter. سيُنشأ مجلد `pre_day2` والملف الموجود بداخله معًا، وتُفتح نافذة تحرير فارغة.

إذا كانت الواجهة مختلفة، فابحث في قائمة الملفات عن الخيار المقابل لـ«ملف جديد». يمكنك أيضًا إظهار القائمة نفسها بالنقر بزر الفأرة الأيمن على المساحة الفارغة أسفل الملفات. واجهة التحرير في Codespace هي محرر يُسمى VS Code. دليل الواجهة الرسمي: [User Interface — Explorer (VS Code Docs)](https://code.visualstudio.com/docs/editing/getting-started/userinterface#_explorer-view)

## المحتوى المطلوب لصقه

الصق محتوى المربع فقط. لا تُدرج اسم الملف أو الرموز المحيطة بالمربع. لا تلصقه في الطرفية. لن نشغّله هذه المرة.

### template.md

```markdown
# تقرير التحقق من صفحة ويب

الصفحة المستهدفة: https://example.com/
تاريخ التحقق ووقته (UTC): {{CHECKED_AT}}
رمز حالة HTTP: {{HTTP_STATUS}}

يُنشأ هذا التقرير استنادًا إلى القالب ونتيجة التحقق.
```

### generate.sh

```sh
#!/bin/sh

# هذا الملف برنامج نصي ينشئ تقريرًا من نتائج التحقق من صفحة ويب.
# تحدد العلامة #! في السطر الأول أن يُشغّل هذا المحتوى ببرنامج اسمه sh.
# النص من # حتى نهاية السطر تعليق توضيحي لا يُنفذ.

# يتوقف فور حدوث خطأ أثناء التشغيل (-e).
# ويتوقف أيضًا عند محاولة استخدام قيمة لم تُعرّف (-u).
set -eu

# ينتقل إلى المجلد الذي يوجد فيه هذا البرنامج النصي.
# يشير $0 إلى مسار هذا الملف نفسه, ويستخرج الأمر dirname اسم المجلد من ذلك المسار.
# يتيح ذلك قراءة ملف template.md المجاور بالطريقة نفسها, أيًا كان مكان تشغيل البرنامج النصي.
cd "$(dirname "$0")"

# يفصل case بين العمليات بحسب عدد الوسائط المضافة عند التشغيل.
# يمثل $# عدد الوسائط المضافة عند التشغيل.
case "$#" in
  # تشير 0 إلى التشغيل دون إضافة أي وسيط.
  0)
    # [1] يصل إلى صفحة الويب ويضع رمز حالة HTTP في http_status.
    #     يعامل الإخفاق على أنه خطأ, ويوقف المحاولة بعد 30 ثانية, ولا يحفظ محتوى الصفحة.
    http_status=$(curl --fail --silent --show-error --location --max-time 30 \
      --output /dev/null --write-out '%{http_code}' https://example.com/)

    # [2] يضع تاريخ التحقق ووقته بالتوقيت العالمي المنسق في checked_at.
    checked_at=$(date -u '+%Y-%m-%d %H:%M:%S UTC')

    # [3] يستبدل العلامتين في template.md بالقيم أعلاه ويكتب الناتج في report.md.
    #     يُستخدم | فاصلًا كي لا تتعطل العملية إذا احتوت القيم على /.
    sed -e "s|{{CHECKED_AT}}|$checked_at|g" \
        -e "s|{{HTTP_STATUS}}|$http_status|g" template.md > report.md

    printf '%s\n' 'تم إنشاء report.md.'
    # تنهي ;; معالجة هذه الحالة.
    ;;

  # تشير 1 إلى التشغيل مع إضافة وسيط واحد.
  1)
    # يمثل $1 الوسيط الأول المضاف عند التشغيل.
    if [ "$1" != "setup-actions" ]; then
      printf '%s\n' 'الاستخدام: ./generate.sh أو ./generate.sh setup-actions' >&2
      exit 2
    fi
    # ينشئ مجلد إعدادات التشغيل التلقائي. إذا كان موجودًا بالفعل, يستخدمه كما هو.
    mkdir -p ../.github/workflows
    # يكتب في الملف المحتوى من السطر التالي حتى ما قبل السطر الذي يحمل WORKFLOW كما هو.
    cat > ../.github/workflows/update-report.yml <<'WORKFLOW'
name: Update report

on:
  push:
    branches: [master]
    paths:
      - pre_day2/template.md
      - pre_day2/generate.sh
      - .github/workflows/update-report.yml
  workflow_dispatch:

permissions:
  contents: write

jobs:
  update-report:
    runs-on: ubuntu-latest
    steps:
      - name: Check out the repository
        uses: actions/checkout@v7

      - name: Check required tools
        run: |
          command -v sh
          command -v sed
          command -v date
          command -v curl

      - name: Generate the report
        run: |
          chmod +x pre_day2/generate.sh
          ./pre_day2/generate.sh

      - name: Commit the changed report
        run: |
          if [ -z "$(git status --porcelain -- pre_day2/report.md)" ]; then
            echo "لا توجد تغييرات في report.md."
            exit 0
          fi
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          git add pre_day2/report.md
          git commit -m "chore: update report"
          git push
WORKFLOW
    # يعرض رسالة تؤكد كتابة الملف.
    printf '%s\n' 'تم إنشاء .github/workflows/update-report.yml.'
    ;;

  # تشير * إلى الحالات التي لا تنطبق عليها أي من الحالتين أعلاه.
  *)
    printf '%s\n' 'الاستخدام: ./generate.sh أو ./generate.sh setup-actions' >&2
    exit 2
    ;;
# ينهي esac بنية case بالكامل.
esac
```

## الحالة المطلوبة عند الانتهاء

- يوجد الملفان داخل `pre_day2` في قائمة الملفات، وعند فتحهما يطابق محتواهما المربعين في هذه الصفحة.
- عند إجراء العملية التي استخدمتها اليوم للتحقق من أسماء الملفات المعدلة، يظهر `pre_day2/`. ستجده تحت عنوان مختلف عما رأيته اليوم لأن الملفات جديدة، ويكفي ظهور `pre_day2/`. في هذه الحالة تكون الملفات محفوظة لكن التغييرات لم تُسجل بعد. سنسجلها في الجلسة القادمة، ولذلك ينتهي العمل هنا هذه المرة.
- سنبدأ الجلسة القادمة من بيئة Codespace هذه. احتفظ بها ولا تحذفها. إذا لم تعد موجودة، فأنشئ بيئة جديدة باتباع خطوات اليوم، ثم أعد إنشاء الملفين وفق خطوات هذه الصفحة.
